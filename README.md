# Future-B: Pure-Jittor Point Cloud Denoising

This repository contains the source code for the "我们都有光明的未来" team's
submission to Track 2 (point-cloud denoising) of the sixth Graphics AI
Challenge. The implementation is **pure Jittor**: it does not import or
depend on PyTorch.

The released code implements a two-stage PGD pipeline: train PGD1 on clean
surface samples, create PGD1-output/clean pairs, then train PGD2 to predict
the remaining displacement. The final inference entry point runs PGD1 and two
FPS4 PGD2 passes.

The historical B-leaderboard result was Total 81.90, CD 70.71, and P2S 93.09.
This number is evidence for the original competition submission, not a
guarantee that a new run will reproduce it exactly. GPU/Jittor versions,
official data access, regenerated caches, and the intentionally unpublished
checkpoints can change the result.

## Environment

The verified runtime used Python 3.10 and Jittor 1.3.10.0. Create the
environment from the tracked declaration:

```bash
conda env create -f environment.yaml
conda activate jittor
export LIBRARY_PATH="$CONDA_PREFIX/lib${LIBRARY_PATH:+:$LIBRARY_PATH}"
export LD_LIBRARY_PATH="$CONDA_PREFIX/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
```

For a pip-based environment, install `requirements.txt` with Python 3.10;
the compiler/runtime packages listed in `environment.yaml` are still needed
for Jittor CUDA compilation. A CUDA-capable GPU is required for practical
training and full-cloud inference.

## Data preparation

No competition data, meshes, point arrays, derived caches, submissions, or
model weights are included in this repository. Obtain the A/B training data
and B-test inputs from the competition organizer under their terms, then keep
them outside Git. The expected layout is documented in
[data/README.md](data/README.md).

The following command creates an A+B training index and deterministic split.
Replace the four input paths with the official data locations. `--seed`
controls the split and is recorded in the generated manifest.

```bash
python scripts/prepare_ab_full_training.py \
  --a-mesh-root /path/to/a_train/shapenet \
  --a-train-split /path/to/a_train_split.json \
  --b-mesh-root /path/to/b_train/shapenet \
  --b-train-list /path/to/b_train.txt \
  --b-validation-list /path/to/b_validation.txt \
  --output-mesh-root data/prepared/shapenet \
  --output-split-dir data/splits/ab_full_seed20260726 \
  --seed 20260726
```

## Training

Build a 50,000-point clean-surface cache, then generate a relocatable PGD1
configuration. The configuration helper writes the actual paths and hashes
from the cache; do not edit hash fields by hand.

```bash
python scripts/build_train_surface_cache.py \
  --mesh-root data/prepared/shapenet \
  --train-split data/splits/ab_full_seed20260726/train.json \
  --output-dir outputs/pgd1_surface_cache \
  --expected-train-split-sha256 "$(sha256sum data/splits/ab_full_seed20260726/train.json | awk '{print $1}')" \
  --expected-split-manifest-sha256 "$(sha256sum data/splits/ab_full_seed20260726/manifest.json | awk '{print $1}')" \
  --seed 20260726

python scripts/configure_pgd1_training.py \
  --template configs/train/pgd_ab35632_gate_e200_noisyfit_cube24_seed20260726.yaml \
  --mesh-root data/prepared/shapenet \
  --train-split data/splits/ab_full_seed20260726/train.json \
  --train-cache outputs/pgd1_surface_cache \
  --output outputs/configs/pgd1.yaml

python scripts/train.py --config outputs/configs/pgd1.yaml --run-dir outputs/pgd1
```

Each training run saves its resolved configuration, command, logs, TensorBoard
events, checkpoints, and manifest under `--run-dir`. `outputs/` is ignored by
Git. PGD2 is trained from a cache generated by, in order,
`build_pgd2_noisy_cache.py`, `run_pgd1_pgd2_shards.py`, and
`build_pgd2_paired_cache.py`; then use `configure_pgd2_training.py`,
`build_pgd2_initial_checkpoint.py`, and `train_pgd2.py`. All of these
commands expose `--seed` or read the seed from the tracked YAML configuration.

## Inference and evaluation

Checkpoints are deliberately not distributed because the project release rule
excludes large training artifacts. With checkpoints that match the SHA-256
values in `configs/inference/`, run full cascade inference as follows:

```bash
python scripts/infer_pgd1_pgd2_pgd2.py \
  --project-root . \
  --input-root /path/to/b_test \
  --output-root outputs/b_predictions \
  --work-root outputs/b_work \
  --pgd1-inference-config configs/inference/pgd1_e200.json \
  --pgd1-checkpoint /path/to/pgd1_e200.pkl \
  --pgd2-inference-config configs/inference/pgd2_e139.json \
  --pgd2-checkpoint /path/to/pgd2_e139.pkl \
  --devices 0 \
  --random-seed 20260819
```

The script requires a new `--output-root` and `--work-root`, verifies input
shapes and checkpoint hashes, and writes an inference manifest. To evaluate
locally, use `scripts/evaluate.py` with prediction, clean-reference, noisy,
and mesh directories supplied from an authorized validation set.

CD is bidirectional Chamfer distance and P2S is point-to-surface distance;
the competition score combines their normalized scores with equal weight.
The official B-test labels are not public, so local validation is only a
selection/reproducibility check, not an independent verification of the
historical online score.
